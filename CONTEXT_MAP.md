# CONTEXT_MAP — Regin

**Last updated:** 2026-02-27

## 1. Purpose Statement

Regin is the DAG pipeline resolver that transforms raw agent definition TOML files through gated stages into platform-ready render formats. It replaces and merges the former `transform_to_universal` (levels 1-7) and `universal_to_canonical` (level 8) into a single project. Gates are compiled Rust (PyO3) modules that handle all file IO — Python code between gates transforms only the delta between checkpoint schemas. This CONTEXT_MAP helps agents orient to where knowledge lives and where to refresh context mid-session.

## 9. Known Issues / Active Work

### Current Build Scope

Levels 1-8 are fully implemented. Level 8 (anthropic resolve) performs 8-step vendor resolution: model lookup, custom tool discovery, grant explosion to vendor tools/commands, security boundary display, hooks configuration, frontmatter composition, critical rules, writing output population. The `agent-anthropic-render` schema may still evolve as the render format matures.

### Schema Naming

Schema `agent-success-reduced.schema.json` (previously referenced as `sf-reduced`) now exists on disk. Schema `agent-includes-resolved.schema.json` has been renamed to `agent-includes-merged.schema.json` to reflect that level 5 is a merge operation.

### Predecessor Projects

`transform_to_universal` and `universal_to_canonical` are the predecessors that Regin replaces. Their code is reference material for behavior — the pure functions contain the domain logic that Regin's pure functions will replicate. Their architecture (sequential step naming, separate loaders/writers, mixed TOML/JSON checkpoints) is NOT to be followed.

### Gate Rebuild

Gates have been rebuilt to handle IO directly. Input gates read TOML files and return JSON. Output gates take JSON and write TOML files. The passthrough gate (`gate_paths_verified`) reads, validates (including path existence), and writes. All checkpoints on disk are TOML. This is a change from the predecessor where some intermediates were JSON and Python code handled file IO.
